# 分析一条解释动画

这份文档提供通用分析方法，用于判断一段动画如何帮助观众理解概念。这里的示例和问题清单为 Concept Reel 重写，不收录第三方短片的字幕、逐帧画面或逆向分镜。

分析的目的，是把有效的讲解手段转成自己的设计决策。观察到的现象、实际量出的数值和自己的推测要分开记录。

## 一、先确定要解释什么

先用一句话写下视频试图回答的问题，再写下观众需要的前置知识。例如，一段关于排队的短片可以回答：为什么队伍在持续处理顾客时仍然变长？观众只需认识“每秒到达人数”和“每秒处理人数”。

不要先给作品打风格标签。先检查它提供了哪些解释证据：

| 观察项 | 要记录的内容 | 可以支持的判断 |
|---|---|---|
| 问题 | 开场提出的疑惑 | 观众为何需要继续看 |
| 条件 | 模型、实验或例子的假设 | 结论在什么范围成立 |
| 过程 | 输入、规则、状态变化、输出 | 画面是否展示了推理步骤 |
| 对照 | 哪个条件变化，哪些条件保持 | 是否能看出变化的原因 |
| 结论 | 观众最终可以复述的内容 | 片尾是否回答了开场问题 |

## 二、用最少的记录重建解释链

只记录理解所需的结构，不抄录完整台词或描述每一帧：

| 段落职责 | 可以记录的问题 |
|---|---|
| 建立情境 | 什么对象让观众认出了问题？ |
| 给出规则 | 规则是通过演示、文字还是公式说明的？ |
| 运行例子 | 观众能否跟踪一个对象从输入到输出？ |
| 做对照 | 比较的是数量、速度、位置还是结果？ |
| 说明边界 | 哪个反例限制了结论？ |
| 收束 | 观众现在能解释哪个最初解释不了的现象？ |

一段作品不必包含所有职责。若删掉某段仍不影响理解，记录它是装饰、情绪还是节奏用途，供自己的作品决定是否保留。

## 三、检查“字幕”和“画面”的分工

字幕可以交代条件、指出观察方向、解释结果。画面可以展示过程、空间关系和同时存在的差异。两者有重叠时，检查这种重复是否帮助阅读。

可以做三种检查：

1. 只读字幕，确认论证是否连贯，是否突然引入未解释的术语。
2. 静音观察画面，确认关键变化是否可见，标注是否足以辨认对象。
3. 合起来观看，确认观众有时间读完字幕并观察动作。

遮住所有文字后认不出抽象图表，并不自动说明图表失败。坐标轴、单位和图例本来就是图表的解释组成部分。

## 四、数值怎么量，结论怎么写

需要测量时，先记录样本来源、分辨率、帧率和方法，再报告结果。没有实际测量的数据，不写成“实测规律”。

| 指标 | 可用方法 | 限制 |
|---|---|---|
| 字幕停留 | 记录首次可读和最后可读的时间 | 淡入淡出阶段的可读性需人工判断 |
| 字体和主体大小 | 在已知画幅截图中量边界 | 换字体和播放设备后仍需复查 |
| 转场时长 | 记录旧画面开始退出、新画面稳定的时间 | 亮度变化不能单独区分闪光和换镜头 |
| 画面亮度 | 比较固定采样方法下的截图 | 全帧均值不能说明局部文字对比度 |
| 输出速度 | 记录机器、浏览器、画幅和渲染模式 | 不可直接推广成所有机器的性能承诺 |

OCR 可以帮助定位字幕，但存在漏字、标点和顺序错误。人物、年份、数字与公式应人工核对。不要仅凭字幕运动或代码风格推断作者使用了哪套提示词或制作工具。

## 五、把观察改写成自己的实验

把“那条片用了什么”转为“我的概念需要什么”。可以保留通用手段，例如同屏对照、逐步揭示和固定颜色含义，再选择自己的例子、叙事和画面。

以排队模型为例，可先设计一个明确标为“示意”的实验：每秒到达 3 个任务，每秒完成 2 个任务。保留全部未完成任务，并显示累计到达、累计完成和当前队列。随后只改变处理能力，让观众比较结果。这里的参数是教学模型，不是对任何真实商店的调查数据。

分镜中记录模型假设、计算方法和想验证的理解结果。若使用公共数据，应保留数据出处、单位、日期和处理方式。

## 六、分析后的交付物

一次分析可以交付以下内容：

- 一个明确的讲解问题和预期结论。
- 一张解释链表，指出每段承担的职责。
- 两到三个准备试用的通用手段，以及它们解决的问题。
- 一个自行设计的小实验或分镜草案。
- 仍需核对的事实、数据与模型边界。

不要将相似的配色、字体或镜头顺序当成理解质量的证据。真正值得验证的是：观众是否能从画面中的条件与过程推导出结果。
