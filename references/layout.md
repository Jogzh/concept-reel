# 版式与画面检查

版式应让对象、关系和文字容易被读到。先确定镜头承担的解释任务，再分配主体、标注、字幕与常驻元素的位置。这里的建议适用于 1920×1080 画布，也需要按实际播放设备复查。

## 一、按信息关系选版式

| 当前要表达什么 | 可以使用的版式 | 要检查什么 |
|---|---|---|
| 两个条件的结果差异 | 左右或上下对照 | 同一尺度、共同起点和单位 |
| 一串操作步骤 | 流程或逐步展开 | 当前步骤与前后关系清楚 |
| 一个对象的细节 | 主体加局部放大 | 放大前后的对应位置 |
| 数量随时间变化 | 图表与当前读数 | 轴、刻度、单位和数据一致 |
| 多个对象的联系 | 网络或分组 | 连接含义和方向明确 |
| 一条结论或定义 | 文字卡与小例子 | 足够的阅读停留 |

相邻镜头可以沿用同一版式。需要比较或建立连续性时，稳定布局有助于理解；信息关系改变时再调整构图。不要为了变化而变化。

## 二、为字幕和常驻元素预留空间

工程默认字幕靠近底部。设计时可以先把下方约 20% 作为字幕预留区，把左上仪表或章节标记的实际范围记入分镜。预留区是起点，不是禁止背景进入的硬边界。

背景、地面和非关键装饰可以延伸到字幕区域，但字幕与关键证据应有足够对比和间距。主角放大、长标注出现、镜头移动时都要检查实际范围，不能只检查初始坐标。

若常驻仪表不承载当前镜头的信息，可以缩小、降低强调或暂时隐藏。若修改 `K.SUB`、`K.gauge` 的默认位置，要同步检查引用它们的工程。

## 三、用实际字宽安排文字

字符数不能准确预测中文、数字和西文混排的宽度。字体加载后，用 `fr.measure(str, options)` 或 `fr.layout()` 量正文，再检查最长一句和最大字号的截图。

字幕过长时可以缩短措辞、分成两句、调整字距或延长时间。不要优先靠缩小字号解决。关键标注也应在目标设备上可读。

需要比较的两组对象最好同时可见。若采取前后展示，应保留共有基线、编号或一个清楚的结果摘要。

## 四、检查空间需要真实截图

当前仓库通过渲染截图检查布局，不提供源码坐标静态检查器。变量、变换、临时层和镜头推进后的边界都需要从结果图中判断。

```bash
python engine/render.py projects/my_film --sheet 16
python engine/render.py projects/my_film --stills 3 8 15
python engine/render.py projects/my_film --motion 7 9 12
```

全片拼图用于发现空镜、重复和整体结构问题。关键静帧用于检查重叠、字宽与局部对比。转场序列用于检查进退场，不能只用一张漂亮的静帧代表整个镜头。

## 五、转场由语义决定

硬切、溶解、压暗和变形都可以使用。需要明确区分条件时，可以直接切换；要保持同一对象身份时，可以保留轮廓、编号或位置；要表示量的连续变化时，避免产生中途消失的错觉。

`K.dips(t, points, half)` 返回亮度系数，在指定时刻附近降低亮度。调用者可以控制最低亮度：

```js
const dim = lerp(.2, 1, K.dips(t, [8, 20], .4));
fr.g({ a: dim }, () => { /* 当前镜头 */ });
```

效果的深度和时长要看截图与播放结果。转场不必每次不同，也不必每次相同。

## 六、跨镜头保留可辨认的锚点

镜头移动或对象变形时，保留一个可辨认的锚点：对象编号、轮廓、刻度、位置或明确的引线。观众应能理解“还是那个对象，只是观察方式变了”。

大幅放大后仍要控制线宽和字号。可以把模型坐标投影到屏幕坐标，再画标签，避免文字随模型一起变得过大。

上游示例 [fold_C](../examples/fold_C/film.js) 展示了空间推进与坐标换算；它继承自 [vibe-know--skill](https://github.com/zhaosenlin12-creator/vibe-know--skill)，来源见 [NOTICE.md](../NOTICE.md)。

## 七、给关键步骤足够时间

章节时长由所需步骤、字幕字数和观察难度决定。复杂对照可能需要比片名更长的停留；只有一个状态变化的镜头可以更短。

分镜中分别安排对象出现、动作进行、结果稳定和离场。片尾若承担解释或模型边界，也需要可读时间，不应只剩一帧。

## 八、自查清单

- [ ] 主体、标注和字幕在最大尺寸时仍清楚分开。
- [ ] 对照的单位、比例、颜色和基线一致。
- [ ] 关键对象在转场前后仍能辨认。
- [ ] 长句、公式和来源行在实际播放尺寸上可读。
- [ ] 字幕出现期间有足够稳定停留。
- [ ] 关键静帧和转场序列已经检查。
- [ ] `--det` 通过，画面和数字来自相同的确定性状态。

## 九、正确理解确定性检查

```bash
python engine/render.py projects/my_film --det
```

当前实现使用固定随机种子选取 12 个时刻，在同一个页面中截图，再打乱顺序重复截图，比较 PNG 的 SHA-256。匹配时返回 0，不匹配或渲染失败时返回非零。它检查这批时刻的重复一致性，不保证所有时刻、所有浏览器和跨机器结果都相同。

失败时先检查 `Math.random()`、跨帧累积、上下文状态和尚未加载的资源。引擎会重置每帧及临时层的 Canvas 状态，并等字体和首帧绘制完成后标记 `READY`。自己的模拟数据仍需固定种子或预计算。

必要时缩小到报告中的时刻，重复 `--stills` 并比较图像，确认差异区域。记录浏览器版本和最小复现后再排查渲染器问题；不要直接把不一致归因于 GPU，也不要靠反复重跑掩盖失败。
