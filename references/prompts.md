# 创作任务与修改提示词

以下模板为 Concept Reel 重写，用于把知识主题变成可实现、可验证的动画任务。它们是通用创作方法，不是对第三方作品提示词的还原。

好的任务描述应给出问题、受众、输出和限制。无法提前确定的细节，可以通过小型预览来决定。

## 〇、开始前需要哪些信息

优先确定主题、观众已经知道什么、看完需要理解什么，以及需要源码预览还是完整视频。时长、外观和声音可以采用合理默认值，随后在首个镜头中验证。

只有影响事实正确性、输出范围或制作成本的缺失信息才值得提前澄清。一般排版、代码组织和可逆的画面调整由执行者直接完成。

## 一、完整任务模板

复制下面的模板并填写方括号。没有要求的项目可以删掉。

```text
使用 Concept Reel 制作一段解释动画。

问题：[观众想知道什么]
受众：[年龄、专业背景、已经认识的概念]
看完应能解释：[一个可检验的理解结果]
时长：[秒数]；画幅：1920×1080；帧率：[默认30]
输出：[工程源码和预览 / 完整MP4及源码]
外观：[C夜曲 / B寓言 / 使用现有外观并适当调整]
声音：[无声 / 合成事件音 / 已有且可使用的配乐路径]

内容依据：[论文、公开数据、官方文档或我提供的材料]
事实要求：区分数据、示意模型和推测；记录关键数字、单位与适用条件。

讲解方式：先选一个能演示机制的最小例子，再组织分镜。
字幕交代条件和结论，画面显示过程或对照；给观众留阅读与观察时间。
颜色、标注、坐标轴和比例保持一致，必要的简化写入分镜或片尾。

实现要求：画面由seek(t)确定；使用固定种子或预计算数据。
使用共享/engine资源，保持工程可预览和可重复渲染。
先整理事实表和storyboard.md，再实现一个关键镜头并检查截图。
在已授权的输出范围内继续完成；遇到影响正确性的缺失事实时明确标出。

验收：检查关键静帧、转场拼图、确定性和输出时长。
若请求完整视频，完成画面渲染、事件音频和音画合成。
交付文件位置、验证结果，以及仍存在的限制。
```

外观是实现手段。任务描述不需要规定每句必须有动画、每章必须换版式或所有转场必须采用同一种效果。

## 二、原创小案例：为什么队伍越处理越长

下面是一个可直接实施的教学模型，不对应任何真实地点的测量。

```text
制作40秒的无旁白动画，解释“为什么一直在处理任务，队伍仍会增长”。
受众认识加减法，尚不了解排队模型。
用C夜曲外观，把任务画成可区分的小卡片，把处理位置画成固定窗口。

模型条件：空队列起步，每秒到达3个任务，每秒完成2个任务。
统一显示累计到达、累计完成和当前未完成；所有数字来自同一份模拟数据。
先让观众看几秒，再指出到达速度超过处理速度。
随后把处理能力提高到每秒4个任务，展示已有积压需要时间消化。
说明这是固定速率的简化模型；真实到达和处理通常会波动。

字幕、动作和计数均由时间确定。为任务分配稳定编号，避免任意seek后位置不同。
先实现最能说明积压形成的一镜，检查同屏计数是否对得上。
完成分镜、代码、拼图与完整MP4，并记录模型假设。
```

这个任务的关键是能核对的因果关系。卡片造型、标题和转场可以自行设计，不需要模仿现有短片。

## 三、把大任务分成可检验的阶段

| 阶段 | 提示词重点 | 应得到的结果 |
|---|---|---|
| 事实整理 | 哪些结论有来源，哪些是教学假设？ | 事实表、来源和待查问题 |
| 分镜 | 每段解决哪个理解障碍？ | 时间、字幕、对象、动作、标注和声音 |
| 关键镜头 | 最难说明的机制是什么？ | 一个可预览的镜头和检查用截图 |
| 整片实现 | 如何连接已有镜头并保持语义一致？ | 完整工程与全片拼图 |
| 验证与导出 | 哪些条件能证明输出符合任务？ | 关键帧、det结果、MP4和必要说明 |

执行阶段之间可以直接推进。预览用于发现问题，不必把每个普通修改都变成一次批准请求。用户明确要求逐阶段确认时，按其要求交付可审阅的结果。

## 四、修改意见要指出可观察的问题

| 看到的问题 | 可以使用的修改提示 |
|---|---|
| 看不懂输入怎样变成结果 | 在[时间段]中保持一个对象可追踪，补出中间状态与规则。 |
| 对比需要来回记忆 | 让[两组对象]同时可见，统一比例、单位和起点。 |
| 字幕读不完 | 缩短[句子]或延长稳定停留，重新抽帧检查进退场。 |
| 图表只给出结论 | 显示生成数据的过程或注明数据来源，检查轴与单位。 |
| 颜色含义变化 | 列出颜色对应的状态，统一[冲突位置]，同时添加标签。 |
| 转场丢失对象身份 | 保留编号、颜色或位置锚点，再选择硬切、溶解或变形。 |
| 主体与字幕重叠 | 调整[对象]的范围或字幕位置，用最大尺寸时的截图验证。 |
| 画面重复且没有新信息 | 删除重复段落，或增加一个只改变单个条件的对照。 |
| 声音盖过阅读节奏 | 降低配乐或事件增益，在字幕揭晓处减少不必要的音效。 |
| 同一时刻截图不一致 | 检查跨帧状态、随机数、未完成的资源加载，运行--det。 |

修改请求可以具体到时间和对象，例如：“12.0–15.0秒，卡片离开窗口后没有进入完成计数，请让位置和数值使用同一份状态数据。”

## 五、交付与来源记录

交付时说明工程目录、运行命令、输出文件、完成的验证和模型简化。引用他人的代码、数据或素材时记录来源与许可；不要用别人的字幕或镜头逐段替换成新标题。
