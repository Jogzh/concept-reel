# 讲解设计：把概念变成可观察的过程

这份文档为 Concept Reel 重写，使用原创教学小案例说明通用方法。画面需要帮助观众理解条件、过程或关系；配色与动效负责让这些信息更容易被看见。

## 〇、画出对象，还要画出关系

给“任务越积越多”配一堆卡片，能够表现结果。若要解释原因，还需同时显示任务怎样到达、怎样完成，以及哪些任务仍在等待。

在分镜中分别写下三件事：观众认识的对象、对象遵守的规则、规则产生的可观察结果。装饰可以辅助辨认，但不能替代缺失的推理步骤。

## 一、先找到最小可运行的例子

从观众已经认识的东西开始，缩小到一段能跟踪的过程。例如解释队列增长，可以使用两个明确标记的量：到达速度和处理速度。先显示一个任务通过系统，再增加到达数量。

| 要解释的关系 | 最小例子 | 需要看见的证据 |
|---|---|---|
| 输入快于输出 | 固定速率的任务队列 | 到达、完成与未完成数量同时更新 |
| 顺序会影响结果 | 两个不同操作作用于同一对象 | 两种顺序的中间状态和最终结果 |
| 局部变化传播 | 少量节点组成的路径 | 变化从哪里开始，经过哪些连接 |
| 规则有适用范围 | 一个满足条件和一个不满足条件的输入 | 条件差异及对应结果 |
| 平均值掩盖差异 | 总数相同但分布不同的两组数据 | 相同的平均值和不同的分布 |

这些例子是设计起点。正式内容仍需核对领域事实、数据和模型假设。

## 二、六种可组合的表达方法

| 方法 | 用来解决什么问题 | 设计要点 |
|---|---|---|
| 观察或预测 | 让观众注意到一个现象 | 留出观察时间，之后再揭示解释 |
| 对象演示 | 让抽象名词有明确对应物 | 说明形状代表什么，必要时附标签 |
| 逐步执行 | 让观众理解一条规则 | 输入、操作、状态和输出保持可追踪 |
| 同屏对照 | 让观众比较条件或结果 | 单位、比例和基线统一，只改变目标条件 |
| 关系图表 | 让观众看出结构和趋势 | 轴、单位、图例和数据来源完整 |
| 文字或公式 | 给过程命名或压缩结论 | 符号对应已有对象，保留必要解释 |

不是每句话都需要一个新画面。同一个场景可以承载多句字幕，只要每次增加或改变的信息明确。

## 三、什么时候运动，什么时候停下来

规则改变、对象转移和数值累积适合用运动显示。定义、条件、公式和重要结果通常需要稳定停留，方便阅读和核对。

设计每个镜头时区分三个时间段：建立对象、发生变化、看清结果。若字幕进入动画占用了阅读时间，可以提前展示对象、简化显影，或者延长结果停留。

硬切可以明确分隔不同条件；溶解可以表现连续过渡；变形可以说明对象保持身份但改变状态。选择由语义决定。闪光、呼吸和粒子运动应控制强度，避免遮蔽正文。

## 四、检查解释是否成立

一段动画应让观众回答：

- 屏上各对象和数字分别代表什么？
- 哪条规则或条件发生了变化？
- 哪个结果可以归因于这次变化？
- 哪些前提限制了这个结论？

对照实验尤其要检查混杂条件。若两组同时改变颜色、位置、数量和处理速度，观众可能不知道究竟在比较哪个变量。

图表和科学示意可以简化，但要说明影响理解的简化。例如物体不按实际比例绘制、模型忽略随机波动、曲线来自人为参数，而不是真实测量。

## 五、给概念选择合适的形象

先选择编码，再选择造型：数量可以对应长度或数量，速度可以对应单位时间内的移动或完成次数，连接关系可以对应路径，状态可以对应标签与颜色。

| 概念属性 | 合适的表达 | 常见误解 |
|---|---|---|
| 数量 | 刻度、计数、相同比例的长度 | 用面积比较却只按半径缩放 |
| 时间 | 共享时间轴或稳定节拍 | 不同镜头加速程度不同却未说明 |
| 位置和包含 | 空间关系、层级和局部放大 | 镜头推进后丢失原始位置 |
| 概率 | 多次试验、分布或有标注的比例 | 少量随机结果被当成稳定结论 |
| 因果 | 条件控制和逐步变化 | 同时发生被画成必然因果 |
| 逻辑规则 | 小输入与逐步状态表 | 输出直接出现，中间规则省略 |

颜色可以强调状态，但同时保留文字、编号或形状提示。不要让观众只凭颜色分辨关键结果。

## 六、文案和分镜一起写

先写预期理解，再写字幕和画面。字幕交代看什么，画面提供能看见的证据。

| 时间 | 预期理解 | 字幕 | 对象与动作 | 标注或单位 | 声音 |
|---|---|---|---|---|---|
| 0–4s | 一个任务如何通过系统 | 任务到达后，先等待处理。 | 一张编号卡进入队列，再进入窗口 | 到达、等待、完成 | 可选轻提示音 |
| 4–10s | 输入输出速度不同 | 每秒到达3个，完成2个。 | 统一节拍下显示到达和完成 | 个/秒；示意模型 | 每秒一个低强度节拍 |
| 10–16s | 未完成数量是两者之差 | 多出的任务留在队列里。 | 未完成卡片保留，等待计数上升 | 累计到达−累计完成 | 无 |

时间是分镜草案，不是固定节奏规定。最难读的字幕、最长的标注和最大尺寸的对象都需要实际截图验证。

## 七、走一遍：用对照解释队列积压

原创教学模型：初始队列为空，到达速度固定为每秒3个任务，单个处理位置每秒完成2个任务。完成任务只能来自已经到达的任务，任何时刻的未完成数不能为负。

1. 先以正常节拍显示几个任务，建立卡片、窗口和计数的含义。
2. 同步显示累计到达、累计完成和当前未完成量。这里未完成量包含正在处理的任务，数值都取自同一份模拟结果。
3. 在两栏对照中保留相同的到达序列，一栏仍每秒完成2个，另一栏提高到每秒4个。
4. 让观众看到第二栏先消化积压，再受到到达量限制；处理能力不等于实际完成数。
5. 最后写明模型条件，指出真实任务到达与处理时间通常有波动。

实现时可以预先生成固定事件表，再按时间查询状态。卡片编号保持不变，任意 `seek(t)` 都应得到同样的位置和计数。

需要学习现有代码组织时，可读 [fold_C 分镜](../examples/fold_C/storyboard.md) 的空间推进和 [pigeon_B 分镜](../examples/pigeon_B/storyboard.md) 的计时安排。来源与许可说明见 [NOTICE.md](../NOTICE.md)。

## 八、看图改图

先看全片拼图检查结构，再看关键静帧和转场序列。使用实际播放尺寸复查文字；截图放大有助于发现边缘、重叠和辉光问题。

| 检查到的问题 | 下一步修改 |
|---|---|
| 对象没有名称或含义 | 增加标签、编号或一次明确的引入 |
| 只看到结果，看不到规则 | 补中间状态，或减慢关键步骤 |
| 比较依赖记住上一镜 | 同屏显示，或保留共享基线 |
| 数值和画面数量对不上 | 使用同一份数据计算位置与计数 |
| 字幕压住关键证据 | 调整构图、字幕位置或展示顺序 |
| 文字在动画期间难以阅读 | 缩短进入效果，增加稳定停留 |
| 转场丢失对象身份 | 保留编号、轮廓或位置锚点 |
| 局部过亮或主体太暗 | 调整局部颜色与辉光，检查实际截图 |
| 同一时刻画面变化 | 检查跨帧状态和资源加载，运行确定性检查 |

```bash
python engine/render.py projects/my_film --sheet 16
python engine/render.py projects/my_film --stills 4 10 16
python engine/render.py projects/my_film --motion 9 11 12
python engine/render.py projects/my_film --det
```

`--sheet` 和 `--motion` 帮助观察，不能自动证明事实正确或字幕可读。`--det` 检查选定时刻的重复截图一致性，也不替代全片内容审查。版式细节见 [layout.md](layout.md)，实现接口见 [engine.md](engine.md)。
